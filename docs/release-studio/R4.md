# Release Studio R4: canonicalization registry

R4 defines the released-byte canonicalizers and the canonical JSON encoder used
by digests and manifests.

## Owned surface

| Path | Role |
| --- | --- |
| `backend/app/release_studio/canonical/` | Registry + per-type canonicalizers + `json.py` |
| `backend/tests/test_release_studio_canonicalization.py` | Acceptance tests |
| `docs/release-studio/R4.md` | This note |

## Rules

Released dossier members are the canonicalized bytes. Each canonicalizer may only
remove or normalize non-manufacturing metadata:

KiCad 10.0.4 writes wall-clock time into more places than one per file, so each
removal below names the emission site it exists for in the pinned source
(tag `f7414d419cae5df2d00e7eaacb16fc0e803799bc`). Missing any single site
silently breaks reproducibility while every semantic test still passes.

- Gerber: drop all three creation stamps — the X2 block `%TF.CreationDate…*%`
  (`include/gbr_metadata.h:52`), the X1 comment form
  `G04 #@! TF.CreationDate,…*` (`gbr_metadata.h:46`), and the plotter's
  unconditional `G04 Created by KiCad (…) date …*` header
  (`common/plotters/GERBER_plotter.cpp:289`). `%TF.GenerationSoftware` is kept.
- `.gbrjob`: drop `GeneralSpecs.CreationDate`, re-emit sorted JSON
- Excellon: drop recognized `; DATE` / `; DRILL file … date …`
  (`gendrill_excellon_writer.cpp:568`) and the NC-drill attribute comment
  `; #@! TF.CreationDate,…` (`gbr_metadata.h:49`), before the header
  terminator only; comments in the drill body are retained
- STEP: replace only the second (`timestamp`) string argument of `FILE_NAME(...)`
  with `PRISM-RELEASE-STUDIO`; the filename and `DATA;` bytes are unchanged
- CSV: drop recognized generated-on comment rows before the CSV header, plus any
  *leading* comment row carrying a real timestamp — which is how
  `place_file_exporter.cpp:229` writes
  `### Footprint positions - created on <iso> ###`. Normalize
  newlines/trailing whitespace without deleting arbitrary comments; comments
  after the header row are always retained
- DRC/ERC JSON: drop only KiCad's top-level `date`; stable-sort violations
- SVG: replace the timestamp inside `<title>SVG Image created as … date …</title>`
  (`common/plotters/SVG_plotter.cpp:806`) with the sentinel, keeping the source
  filename as provenance; strip `<metadata>` and date-bearing comments while
  preserving an XML declaration at byte zero. Comment stripping is tempered so
  a match can never span from one comment to a later one and delete the artwork
  between them
- Board stats JSON: drop `metadata.date`
- PDF: clear `/Info`, source trailer `/ID`, and root `/Metadata` XMP; save with
  `pikepdf` using `deterministic_id=True` and generated object streams. A
  ReportLab producer must set `reportlab.rl_config.invariant = 1` before render;
  Release Studio does not create ReportLab inputs itself.
- Archive: own tar writer (`mtime=0`, uid/gid 0, empty uname/gname, sorted members, gzip `mtime=0`); member names are POSIX-safe

Canonical JSON (`canonical_json` in `release_studio/canonical/json.py`) uses
`sort_keys=True`, `separators=(",",":")`, `ensure_ascii=False`, recursively NFC
normalizes strings, rejects non-string object keys and NFC key collisions, and
passes `allow_nan=False`. This deliberately differs from
`JobArtifactService.prepare_json`, which omits `sort_keys` and NFC normalization.
The legacy `canonical.encoding` import path re-exports the same implementation.

The public registry identity is `release-studio/r4.2`, with per-name version `1`.
Supported names include `gerber`, `gbrjob`, `excellon`, `step`, `csv`,
`drc_erc_json`, `svg`, `pdf`, `board_stats_json`, `archive`, `json`, `manifest`,
and `attestation`.

## Fixture provenance

R4 does not add a directory below `fixtures/release-studio`; R0's exact root
contract remains `{synthetic, usb-pd, cynthion, cli-recordings}`. The semantic
acceptance suite copies the durable `synthetic` R0 fixture into a temporary
directory and uses the pinned `kicad-cli 10.0.4` executor to generate Gerbers,
the `.gbrjob`, Excellon drill, STEP, SVG, DRC/ERC JSON, PDF, and BOM CSV. The SVG
source is the durable Cynthion fixture, whose board file pins `(svgprecision 6)`;
KiCad 10 exposes that as a board plot setting rather than a separate SVG CLI
flag. Board stats are the direct KiCad JSON statistics wrapped in the Release
Studio metadata projection and include the source SHA-256. No handcrafted miniature
output is used as an acceptance fixture. The live test skips on an ordinary
host without KiCad and fails closed when the R0 executor contract is active but
unavailable.

The generated files are removed with the test's temporary directory. This keeps
provenance tied to the durable R0 source and prevents generated outputs from
becoming an additional R0 fixture root.

## Validation

```sh
cd backend
python -m unittest tests.test_release_studio_canonicalization -v
```

The strict pinned-executor runner includes this module in `LIVE_MODULES`. Its
host-safe JSON/registry/archive tests run in the ordinary backend job, while
the generated semantic class uses `requires_kicad_cli()` and therefore is
required to run with zero skips in `kicad-live`.

## Reproducibility guard

`ReleaseStudioVolatileTimestampTests` asserts the property the digest graph
actually depends on: no canonicalized member retains an ISO-8601 instant, and
two exports of the same source at different wall-clock times canonicalize to
identical bytes. It runs in the **default** gate using byte shapes transcribed
from the pinned KiCad source, because the live semantic tests skip without
`kicad-cli` — which is how unremoved timestamps shipped in the first place.

The per-type semantic tests assert removal properties directly rather than
re-applying the production regex to build their own expectation; a test that
recomputes the implementation can only fail if the code differs from a copy of
itself.
