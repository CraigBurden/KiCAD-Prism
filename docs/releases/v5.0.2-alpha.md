# KiCAD Prism v5.0.2-alpha

A bug-fix release for v5.0.1-alpha. It fixes what running v5.0.1-alpha on a
production installation turned up: design data that never caught up after the
upgrade, boards and schematics that would not build or showed only their root
sheet, and viewers that were slow to open over a VPN.

**Back up before upgrading.** Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.2-alpha/docs/UPGRADES.md).
There are no schema migrations and no new required `.env` settings.

**Every design bundle is rebuilt once.** `prism-kicad` moves from 0.13.0 to
0.14.0 and bundles are keyed by its version, so after the upgrade the worker
rebuilds each project's prebuilt revisions in the background. Each project's
newest commit is now rebuilt first (below), so every project's main view is
usable again before older revisions are filled in.

## Design data

- The background prebuild no longer starves projects. Each pass first builds
  the newest commit of every project, then fills older revisions one per
  project, and keeps going while build slots are free instead of stopping
  after one build.
- `PRISM_DESIGN_BUNDLE_CONCURRENCY` runs more than one bundle build at a time
  on a host with the memory for it. It stays `1` by default; see
  [CONFIGURATION](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.2-alpha/docs/CONFIGURATION.md).
- A schematic whose copied symbol units share one UUID, which KiCad keeps as
  written, no longer fails the bundle with `member-schema-invalid … repeats an
  earlier item`.
- A revision whose 3D model is a Git LFS file that is not available builds with
  a `model-unavailable` warning instead of failing with I14.
- Sync fetches the LFS objects of every revision the prebuild keeps, not only
  recent ones.
- **Project Settings → Design data** says why a revision failed (the stage's
  error code, message and file and line) and lists failed builds with their
  error. Revisions fill in as they are rebuilt after the upgrade.
- The panel keeps its counts current while a rebuild runs, and loads quickly on
  large projects.
- A bundle whose board or models stage fails internally is rebuilt from the
  start on retry, instead of failing the same way on every attempt.
- A bundle job's details record the peak memory and time of each KiCad step it
  runs (`kicad_steps`: upgrade, zone refill, GLB export), beside `prism-kicad`'s
  own `invocations`.

## Schematic sheets

Sheet files are now found the way KiCad 10.0.6 finds them, in one place that
every part of Prism uses: the project's text variables and `${PROJECTNAME}` are
expanded, `\` is read as `/`, a path is relative to the sheet that names it,
and a file whose name differs only in letter case is used, as on Windows and
macOS. A design whose root names `subsheets/` for a `Subsheets/` folder now
shows all of its sheets instead of only the root.

## Viewer loading

Measured over the production VPN, opening a large design's schematic took
9–18 s and downloaded the board alongside it; reopening it downloaded
everything again.

- A file read at a full commit SHA is cached by the browser for good, and
  every source carries an ETag from its content, so an unchanged file is
  answered 304 without its bytes.
- Large boards, schematics, sheet listings and design indexes are compressed
  once, outside the request loop, and reused; other requests no longer stall
  for seconds while a large design downloads.
- The board loads after the schematic on screen instead of competing with it,
  and the assembly page is no longer downloaded until its tab is opened.

## Installer

- The capacity presets set `PRISM_WORKER_MEMORY_BUDGET_MIB` (half the worker
  container), `PRISM_DESIGN_BUNDLE_CONCURRENCY` (two builds on the large preset)
  and the bundle memory budget that concurrency needs.
- Re-running the installer keeps every value you changed in `generated/.env`,
  including preset values, and an answers-file run reuses the existing database
  password and session secret.
- `.env.example` lists `CATALOG_WORKER_CPU_LIMIT` and
  `CATALOG_WORKER_MEMORY_LIMIT`.

## Other fixes

- Opening a project no longer makes a failing Simulation Studio request when it
  is turned off.
- A bundle that could not be built is reported once in the viewer, not twice.
- In the command palette, a short query one letter off no longer matches (for
  example `GND` no longer lists `GNSS_RECEIVER`).

## Changes you may notice

- `GET /design-bundles` adds `reason` to each incomplete revision and a
  `failedBuilds` list, and its `storedBytes` now counts the stored archives
  only, not their unpacked cache.
- `GET /api/auth/config` adds `sim_studio_enabled`.

## Known issues

- Where a sheet repeats a sheet-pin name, the `_N` numbers can be assigned in a
  different order from KiCad's. The nets themselves match.
- A board file with a missing parenthesis that KiCad tolerates, such as
  `(curved_edges no)filter_ratio 0.9)`, fails to parse.
- Page numbers of a multi-root project's top-level sheets are not yet checked
  against KiCad.
- Simulation Studio is experimental.
- Commits saved by a KiCad 8.99 nightly with experimental rule-area syntax
  cannot be read by KiCad 10, so their bundles fail with "KiCad cannot read …".
- One board's bundle build has been seen failing with `upgrade-record-invalid`;
  it is not yet investigated.
- The bundle stage memory caps, and the bundle memory budget the installer
  derives from them, are provisional; this release records each step's real
  peak so they can be sized from production numbers.
- Once, a board's models stage failed on an archive that a fresh build of the
  same commit accepted. The cause is not found; the retry now rebuilds.

This is an alpha release for Linux AMD64. Publication creates only the
`5.0.2-alpha` image tag. The release archive pins the exact images and
includes these notes, the upgrade guide, the backup tool and checksums.
