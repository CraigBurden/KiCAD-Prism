# KiCAD Prism v5.0.0-alpha

This release brings together the features and fixes added since v4.0.0-alpha.
The largest change is the native design bundle: each revision is parsed once,
by one Rust parser, and every feature reads the result.

**Back up before upgrading.** Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/UPGRADES.md):
take and verify a backup with this release's `prism_backup.py`, then start the
new images. Schema migrations run on the first start. The catalog is
forward-only, so going back to v4.0.0-alpha means restoring that backup;
changing the images alone is not enough. An upgrade from v4.0.0-alpha and a
restore back to it were both rehearsed on a seeded installation before this
release.

On the first start the worker builds design bundles for each project's recent
commits and tags in the background. Screens show "Preparing design data…" until
a revision's bundle is ready.

## Native design bundle

- A revision is parsed once by `prism-kicad` into a design bundle. The project
  card, schematic and PCB viewers, 3D view, BOM, variants, Design Comparison,
  catalog import and Release Studio all read it. A commit that leaves the
  design files unchanged reuses the previous bundle.
- Bundles are prebuilt for each branch's newest commits and for every tag.
  **Project Settings → Design data** shows status and storage, with Rebuild for
  HEAD and Rebuild all. A failed build shows **Retry**.
- The 3D tab draws the bundle's board off the main thread. The mesh/glTF path
  and its readiness jobs are gone.
- Design Comparison runs on bundles, so comparing two built revisions takes
  seconds. Fabrication comparison still runs KiCad.
- On a large board, parsing a revision went from 84.7 s to 5.3 s.

See [Design data](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/PROJECT_WORKFLOWS.md#design-data)
and the design bundle settings in [Configuration](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/CONFIGURATION.md).

## Release Studio

- **Gerber viewer**: a Gerber tab in Outputs and viewer buttons in the Assets
  Portal, with the placement file checked against the BOM. Most of the viewer
  is Matteo Parenti's work.
- Outputs has a collapsible release-checks rail (DRC/ERC, unpinned models,
  sign-off, manufacturer pack) and a collapsible run history.
- Documents are drawn by `prism-kicad`. The Prism sheet style is the default
  (`sheet_style: prism|kicad`), with ISO 128 line weights, DNP hatching and
  legend, testpoint callouts, mirrored bottom views and continued long tables.
  The fabrication sheet's scale caption no longer overprints the width
  dimension.
- 3D models from outside the repository, such as the stock KiCad library, are
  hashed into the build inputs. If a build has models it cannot pin, approve
  and publish ask for an acknowledgement.
- A monorepo subproject reads only its own `.prism/release-studio/configurations/`.

## Library Manager and catalog

- Library Manager uses studio tabs for Catalog, Bulk Edit, Import Centre and the
  release queue, and one-line rows throughout. The component workspace's
  Assets tab groups files by type with one preview.
- Import sessions can be deleted, and the session list counts only open
  candidates.
- Released STEP files are kept during maintenance. Superseded draft STEP files
  wait 30 days in quarantine (`CATALOG_DRAFT_MODEL_QUARANTINE_DAYS`), and every
  purge is recorded.
- `check_catalog_asset_files.py` reports and restores missing asset files.
  Health reports released revisions whose files are missing.
- The DBL export is rebuilt atomically with stable keys and ships its 3D models.

## Remote Symbol Provider 0.4.0

- Placed symbols carry their catalog component and revision. Prism records which
  catalog revision each synced commit placed.
- Placed footprints embed their 3D models (`REMOTE_PROVIDER_EMBED_3D_MODELS`,
  cap `REMOTE_PROVIDER_EMBED_MAX_COMPRESSED_BYTES`, default 16 MiB), so a fresh
  clone renders without the remote library folder.
- An exact earlier released revision can be placed.

## Comments and trackers

- Rich comments: a WYSIWYG composer, pasted snips, attachments, reactions,
  edits and quotes, a snips gallery, unread markers, and a Markdown export of a
  discussion. Attachments are carried to GitHub and GitLab issues.
- Each tracker connector reports one status: ready, linking-only, needs-test,
  paused or revoked.

## Viewers

- PCB and schematic insets, themed with Prism tokens and chainable. A PCB inset
  switches to 3D with T.
- Point-to-point measure in the PCB tab (Cmd/Ctrl+Shift+M).
- Custom page layouts load with their sheet, and variant DNP markings redraw
  correctly. Viewer shortcuts no longer fire while typing in a text area.

## Projects and history

- A project that shares a folder with another lists only its own commits,
  starting from the commit that added its project file. A failed comparison
  says why.
- Project settings (name, description, paths) are stored in Prism instead of
  being written into the checkout, so a settings edit no longer blocks Sync.
- "Last updated" shows the repository sync time.
- A Help menu with Report a bug and About; the login page shows the build.

## Simulation Studio (experimental)

DC IR drop on a revision's design data: a setup editor, a run queue and result
overlays. It is off by default (`PRISM_SIM_STUDIO_ENABLED`). Its engines come
from a private release, so the published images do not include them; see
[Simulation Studio](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/SIMULATION_STUDIO.md).

## Removed

- **System Builder.** It was never in a tagged release. An installation that
  ran `dev` between 2026-10-09 and 2026-10-23 loses its systems on upgrade; see
  [UPGRADES](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/UPGRADES.md#system-builder-data-is-dropped).
- The mesh 3D path, the Python semantic index and visualizer stores, and the
  Node diff parser. Their on-disk stores under `.kicad-prism/` are deleted on
  the first start.
- `PRISM_PCB_GEOMETRY_BACKEND`, `PRISM_KICAD_NATIVE_TIMEOUT_SECONDS` and
  `PRISM_WEBGPU_CONCURRENCY` are no longer read; remove them from `.env`.

## Deployment and operations

- New `.env` settings, all with defaults: `COMMENT_ATTACHMENT_*`,
  `PRISM_DESIGN_BUNDLE_*`, `PRISM_ZONE_REFILL_TIMEOUT_SECONDS`,
  `REMOTE_PROVIDER_EMBED_*`, `CATALOG_DRAFT_MODEL_QUARANTINE_DAYS`, and
  `PRISM_CADDY_HTTP_PORT` / `PRISM_CADDY_HTTPS_PORT` for the bundled proxy.
  Compare your `.env` with the new `.env.example`.
- Plan disk for design bundles (about 47 MB per prebuilt revision of a large
  board) and worker memory for bundle builds (about 2.2 GB each).
- Startup refuses a `BOOTSTRAP_ADMIN_PASSWORD` that fails the password policy.
- `/git/` (Git Smart HTTP) is proxied through the frontend.
- Lower idle load: no fetch when the remote is unchanged, and old jobs, events
  and logs are pruned.
- A bare LAN IP behind Caddy needs `default_sni`; see
  [HTTPS and TLS](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/HTTPS_AND_TLS.md#bare-ip-addresses).
- Restoring a backup over a database a newer release has migrated now works,
  so a rollback after an upgrade can be done with `prism_backup.py restore`.
- Building from source needs Node 24.22.0 and npm 11.19.1.

API clients: error bodies now carry a `code` beside `detail`, bearer tokens
need `api:read` for every read, and comment and catalog edits take `If-Match`
preconditions. See [UPGRADES](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.0-alpha/docs/UPGRADES.md#api-clients).

## Known issues

- Simulation Studio is experimental.
- Commits saved by a KiCad 8.99 nightly with experimental rule-area syntax
  cannot be read by KiCad 10, so their bundles fail with "KiCad cannot read …".
  Current commits are unaffected.
- One board's bundle build has been seen failing with `upgrade-record-invalid`;
  it is not yet investigated.

This is an alpha release for Linux AMD64. Publication creates only the
`5.0.0-alpha` image tag. The release archive pins the exact images and
includes these notes, the upgrade guide, the backup tool and checksums.
