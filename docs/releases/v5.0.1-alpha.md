# KiCAD Prism v5.0.1-alpha

A bug-fix release for v5.0.0-alpha. It fixes what deploying v5.0.0-alpha on a
production installation turned up: designs the parser could not read, design
bundles that failed quietly, and gaps in the backup tool and installer. It also
adds KiCad 10 multi-root projects.

**Back up before upgrading.** Follow the [upgrade runbook](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.1-alpha/docs/UPGRADES.md)
and use this release's `prism_backup.py`, which now saves more of the
deployment (below). There are no schema migrations and no new `.env` settings.

**Every design bundle is rebuilt once.** `prism-kicad` moves from 0.10.0 to
0.13.0 and bundles are keyed by its version, so after the upgrade the worker
rebuilds each project's prebuilt revisions in the background. Screens show
"Preparing design data…" until a revision's bundle is ready again; on a large
installation this takes a while.

## Schematic parsing

Checked net for net against KiCad 10.0.6's netlist on the deployment's own
designs and on kicad_monkey's 217-project corpus, where 202 of the 206 projects
KiCad can netlist now match exactly.

- KiCad 9 private fields (`(property private …)`) no longer fail a schematic.
- A sub-sheet whose file differs only in letter case, as Windows and macOS
  allow, is read with a `sheet-path-case` warning. A missing sub-sheet is empty
  with a `sheet-missing` warning, as in KiCad, instead of failing the parse.
  Backslash sheet paths resolve.
- **KiCad 10 multi-root projects**: every sheet a project lists as a top-level
  sheet is read, and local nets carry the sheet name (`/Main/SIG`). A listed
  sheet that is absent gives `top-level-sheet-missing`.
- Net connectivity now follows KiCad in more cases: bus entries and global
  buses, a global label meeting a local label of the same name, stacked
  no-connect pins, sheet pins inside a bus, local power ports, labels written
  `A/B` and `A{slash}B`, and the older `unconnected` pin type.
- Net names now follow KiCad: unit display names, alphabetical choice between
  equal global labels, the bare name kept by the last of several nets named by
  one sheet-pin name, and an unconnected pin named `~` gives
  `unconnected-(R1-~-Pad1)` in files saved by KiCad 10.
- Connectors with two pins of one number (mounting pads), duplicate symbol
  UUIDs, footprints identified by `tstamp`, `(module …)` footprints and
  repeated 3D model fields no longer fail or merge.

## Design data

- A bundle whose parse failed or was partial is reported as incomplete:
  "Design bundle incomplete: …" in job history, and the incomplete revisions in
  **Project Settings → Design data**.
- The first build after startup no longer fails with "-o's directory does not
  exist".
- A job that succeeds on retry no longer keeps its earlier error.
- Projects registered before the project-file anchor existed get it on the
  next start and then build bundles.

## Backup and installer

- `prism_backup.py` records the running images and release, and saves
  `data/secrets` (the Release Studio signing key), the Caddy data volume
  (issued certificates), `generated/` and `sites/`. Restore brings
  configuration back only with `--with-config`. Older archives still verify
  and restore.
- Backups stage beside the output archive instead of the system temp
  directory, and the application restarts before the archive is hashed and
  written, so it is down for less time. On Windows with Docker Desktop, expect
  about 2 minutes per GB of `data/projects`.
- `prism_backup.py` runs on its own when fetched from a tag.
- The installer pins `PRISM_ENV_FILE=generated/.env`, so settings in that file
  reach the backend and workers, and its Caddyfile imports `sites/*.caddy`,
  which it never rewrites. Move any extra site you added to
  `generated/Caddyfile` into `sites/<name>.caddy` before re-running it; see
  [UPGRADES](https://github.com/krishna-swaroop/KiCAD-Prism/blob/v5.0.1-alpha/docs/UPGRADES.md#5-get-the-new-code).
- The installer's text UI works on Windows consoles that cannot print its
  symbols.
- `generated/`, `sites/` and backup archives are kept out of the Docker build
  context.

## Changes you may notice

- Net names that now follow KiCad differ from those v5.0.0-alpha showed, for
  example `unconnected-(R1-~-Pad1)` instead of `unconnected-(R1-Pad1)`. A
  Release Studio scope fingerprint that includes such a net differs from the
  same scope released on v5.0.0-alpha.
- `GET /design-bundles` adds `incomplete` counts and revisions. The change is
  additive.

## Known issues

- Where a sheet repeats a sheet-pin name, the `_N` numbers can be assigned in a
  different order from KiCad's. The nets themselves match.
- A board file with a missing parenthesis that KiCad tolerates, such as
  `(curved_edges no)filter_ratio 0.9)`, fails to parse.
- Page numbers of a multi-root project's top-level sheets are not yet checked
  against KiCad.
- Simulation Studio is experimental.
- Commits saved by a KiCad 8.99 nightly with experimental rule-area syntax
  cannot be read by KiCad 10, so their bundles fail with "KiCad cannot read …".
- One board's bundle build has been seen failing with `upgrade-record-invalid`;
  it is not yet investigated.

This is an alpha release for Linux AMD64. Publication creates only the
`5.0.1-alpha` image tag. The release archive pins the exact images and
includes these notes, the upgrade guide, the backup tool and checksums.
